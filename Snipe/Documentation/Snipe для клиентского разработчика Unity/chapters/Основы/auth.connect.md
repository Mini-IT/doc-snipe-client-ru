# Отличие `auth.bind` от `auth.connect`

`auth.bind` - это привязка `(Snipe Account) - (Внешний ID)`

`auth.connect` - это привязка `(Внешний ID A) - (Внешний ID B)`

# Как работает `auth.bind`

Имеется аккаунт Snipe (или создаётся новый при первом обращении). Далее приложение получает какой-то внешний идентификатор, по которому потенциально можно будет найти этого же пользоваетля, если данные для прямого логина в Snipe потеряются. В этом случае на сервер отсылается `auth.bind` с указанием данных внешнего идентификатора (DeviceID, AdvertisingID, FacebookID и т.п.). Т.е. выполняется привязка внешнего идентификатора к аккаунту Snipe. Привязок может быть несколько - по любому из этих внешних идентификаторов можно будет найти аккаунт Snipe.

Если пользователь переустановил приложение или начал использовать другое устройство, то данных об аккаунте Snipe у приложения нет никаких. Поэтому сценарий повторяется. Т.е. при первой же возможности регистрируется новый аккаунт. Далее приложение получает какой-то внешний идентификатор (например FacebookID), но при попытке привязать его через `auth.bind` (или при проверке через `auth.exists`), выясняется, что этот ID уже привязан к другому аккаунту.

Чтобы перелогиниться в старый аккаунт, нужно получить его "логин + пароль". Для этого делается вызов `auth.reset`. Т.е. клиент "говорит" серверу: "дай мне ключи доступа к твоему аккаунту, у которого FacebookID == 'xxx'. Теперь этот пользователь играет остюда". Сервер перепроверяет данные и отдаёт ключи (старые ключи при этом уничтожаются). Клиент реконнектится и логинится уже новыми ключами в тот старый аккаунт.

# Как работает `auth.connect`

Имеется аккаунт Snipe. К нему через `auth.bind` уже привязаны DeviceID и FacebookID.
Пользователь установил приложение на другое устройство. Сценарий повторяется: создаётся новый аккаунт Snipe, к нему привязывается новый DeviceID (другое устройство - назовём его `DeviceID_New`).
Позже появляется FacebookID и выясняется, что этот ID уже привязан к другому аккаунту.

Клиент вызывает `auth.connect`, т.е. "говорит" серверу: "Юзер `FacebookID` играет на двух разных устройствах сразу (по очереди). Запиши себе, что `DeviceID_New` - это одно из устройств того же самого старого аккаунта"

Далее, чтобы перелогиниться в старый аккаунт, нужно точно также получить ключи через `auth.reset`.

# `auth.registerAndLogin`

На практике это может выглядеть немного иначе из-за того, что некоторые шаги "склеены" в один запрос. Так запрос `auth.registerAndLogin` сразу получает на вход DeviceID и сервер сам проверяет, есть ли у него такая привязка. Если есть, отдаёт старый аккаунт. Если нет - регистрирует новый и сразу привязывает (без необходимости отдельно вызвать `auth.bind`).
Поэтому `auth.registerAndLogin` можно использовать также и для перелогинивания (вместо отдельного вызова `auth.reset` и последующего логина).
